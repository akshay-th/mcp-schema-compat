# mcp-schema-compat

**Make any MCP server's tool schemas work with Gemini, OpenAI strict mode and Anthropic.**

MCP servers publish their tool parameters as full JSON Schema, usually generated by Zod or Pydantic. Model providers accept only part of it, and each provider accepts a different part:

| Provider | Typical failure |
|---|---|
| Gemini | `400 Invalid JSON payload received. Unknown name "exclusiveMinimum"`, `"additionalProperties"`, `"$ref"`, `"$schema"`, `"const"` ... and `properties: should be non-empty for OBJECT type` |
| OpenAI `strict: true` | every property must be `required`, every object needs `additionalProperties: false`, no `minLength`/`default`/`allOf` ... |
| Anthropic | `input_schema does not support oneOf, allOf, or anyOf at the top level` |
| OpenAI / Anthropic | tool names must match `^[a-zA-Z0-9_-]{1,64}$`, so `github.create_issue` fails. OpenAI caps a request at 128 tools |

Until now, the fixes for these problems lived inside individual frameworks: LangChain patches, Zed's Gemini code, provider SDKs. `mcp-schema-compat` provides them as one zero-dependency package you can use in three ways:

- **`lint`**: show exactly what a server's tools will break on, per provider. Exits non-zero, so you can use it in CI for servers you maintain.
- **`fix`**: rewrite a `tools/list` dump or a single schema.
- **`proxy`**: wrap any stdio MCP server. Its `tools/list` responses are fixed on the fly, and tool calls are mapped back, so the server never notices.

## Quick start

```bash
# What breaks if this server is used from Gemini?
npx -y github:akshay-th/mcp-schema-compat lint --target gemini -- npx -y @modelcontextprotocol/server-github

# All targets, from a saved tools/list result
npx -y github:akshay-th/mcp-schema-compat lint tools.json

# Rewrite a schema for OpenAI strict mode
cat schema.json | npx -y github:akshay-th/mcp-schema-compat fix --target openai-strict -
```

Example output:


## Proxy mode

Put the proxy in front of the real server command in your client's MCP config. Here is Gemini CLI's `~/.gemini/settings.json`:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": [
        "-y", "github:akshay-th/mcp-schema-compat", "proxy", "--target", "gemini", "--",
        "npx", "-y", "@modelcontextprotocol/server-github"
      ]
    }
  }
}
```

What the proxy does:

- It rewrites `tools/list` responses for the target and passes all other messages through unchanged.
- **It renames invalid tool names and maps them back.** If a tool is exposed as `github_create_issue`, a `tools/call` for it reaches the server as `github.create_issue`.
- **It round-trips free-form objects.** Gemini rejects objects with no declared properties, such as `headers: Record<string,string>`. The proxy exposes those parameters as JSON-encoded strings and `JSON.parse`s them back before the call reaches the server.
- **It handles stdout pollution.** If the server prints logs to stdout, which corrupts the JSON-RPC stream in most clients, the proxy moves those lines to stderr.

## What gets rewritten

Constraints a target can't express are not dropped silently. They are appended to the `description`, for example `(> 0; multiple of 5)`, so the model still sees them. Every rewrite is reported with its JSON-pointer path and whether it is **lossy**, meaning the target schema accepts values the original would reject.

| Rule | gemini | openai-strict | openai | anthropic |
|---|:-:|:-:|:-:|:-:|
| Inline `$ref` / `$defs` / `definitions` | ✓ (recursion cut) | ✓ (recursive refs kept) | | |
| `allOf` → merged object, `oneOf` → `anyOf` | ✓ | ✓ | | |
| `const` → single-value `enum` | ✓ | | | |
| `type: ["x","null"]` → `nullable: true` | ✓ | | | |
| `nullable: true` → `type: ["x","null"]` | | ✓ | | |
| `exclusiveMinimum/Maximum` → `minimum/maximum` + hint | ✓ | | | |
| Unsupported `format` → description | ✓ | ✓ | | |
| Non-string `enum` → description | ✓ | | | |
| Free-form objects | → JSON string (proxy decodes) | locked + reported | | |
| Optional props → required + nullable, `additionalProperties: false` | | ✓ | | |
| Strip unsupported keywords (allowlist) | ✓ | ✓ | | |
| Top-level `anyOf`/`oneOf`/`allOf` → one object | | ✓ | | ✓ |
| `required` entries that don't exist | ✓ | ✓ | ✓ | ✓ |
| Tool name sanitising + unique renames | ✓ | ✓ | ✓ | ✓ |
| 128-tool limit, nesting depth, property count | | ✓ | ✓ | |

## Library

```js
import { fixSchema, fixTools, lintTools, decodeArguments } from 'mcp-schema-compat';

const { schema, changes } = fixSchema(zodJsonSchema, 'gemini');

// MCP ({inputSchema}), OpenAI ({parameters}) and Anthropic ({input_schema}) shapes all work
const { tools, renames, coerce } = fixTools(mcpTools, 'openai-strict');

// When a model calls a renamed tool / sends JSON-string args:
const original = renames[call.name] ?? call.name;
const args = decodeArguments(call.arguments, coerce[call.name]);
```

Each change has the shape `{ path, rule, message, lossy, kind: 'fix' | 'warn' }`. `warn` marks a problem that was detected but couldn't be fixed automatically, such as nesting deeper than strict mode allows.

## Notes and limits

- Provider rules live in [`src/targets.js`](src/targets.js) with comments. Providers do change them, so PRs with references are very welcome.
- Remote `$ref`s (`https://...`) aren't fetched. They are reported and replaced with an untyped schema.
- When a value is collapsed from `anyOf`, the proxy can't decode it, because it doesn't know which branch the model chose. Only plain `properties`/`items` paths are round-tripped.
- Requires Node 18+. No dependencies.
